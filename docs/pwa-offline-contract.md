# PWA / オフライン保存契約

災害板のPWAは、通信が戻ったときに最新情報を取り直すための仕組みではなく、利用者が通信できる間に明示保存した地域を、通信断中に読み取り専用で確認するための補助線です。

## 保存するもの

- 利用者が市区町村ページの「この地域を端末に保存」を押したときだけ保存する
- 保存先はブラウザの IndexedDB。自動保存、訪問しただけの保存、投稿のキューイングはしない
- 場所カードの名前・種別・住所・出典・データ基準日・地図検索URL
- 保存時点の公開報告の判定・立場・鮮度・件数（自由記述メモは保存しない）
- 保存時点の公式確認と出典URL

## 保存しないもの

- `moderation_status`、`review_status`、管理者ID、token、Authorization
- 投稿の自由記述メモ
- Turnstile、rate-limit HMAC、管理APIなどの secret
- 個人間の連絡先や待ち合わせ情報

## 表示契約

- オフライン画面の先頭に保存日時を固定表示する
- 「保存時点の参考情報」であり、営業・開設・安全を保証しないと表示する
- 通信が戻ったら通常ページを開いて最新情報を確認するよう案内する
- オフライン中の投稿・確認・自動送信は完了扱いにしない
- モデレーションの非表示は、通信断中には端末へ伝わらない。再接続時に通常ページを開くまで、保存時点の表示が残る可能性を明示する
- オンラインでオフライン画面を開けた場合は、公開データのリビジョンを照合し、更新・非表示変更があれば古いスナップショットを表示しない

## Service Worker の境界

Service Workerがキャッシュするのは、manifest・アイコン・オフラインシェル・オフライン用スクリプトだけです。

次はキャッシュしません。

- `/a/*` の動的HTML
- 場所詳細ページ（`private, no-store`）
- `/api/*` の動的レスポンス
- POST、通報、管理操作

Worker側のOpenNavi Cache API（`PUBLIC_READ_CACHE=off/shadow/on`）は、通信できる利用者の公開GETを軽くするための別レイヤーです。端末の明示保存とは混ぜません。

## サイズと鮮度

- 1地域あたり最大500場所、2MiBまで
- スナップショットには保存日時とOpenNaviの生成時刻を含める
- 投稿の追加・モデレーション変更を検知する公開リビジョンを含め、再接続時に照合する
- 端末のデータ削除、IndexedDB非対応、容量不足は保存失敗として表示する
- 初回実装では、保存した報告の自由記述を含めず、取り消し漏れの影響を小さくする

## リポジトリ境界

- この契約・UI・Service Worker・IndexedDB projectionは公開 `saigaiban` が正本
- 非公開 `saigaiban-ops` は本番設定、デプロイ、キャッシュロールアウト、監視・負荷試験だけを持つ
- opsへアプリケーションコードや利用者の保存データをコピーしない
